# Raw H.264 files (2026-11-09)

A plan, decided on by the owner (below); nothing here is built yet. It follows #453, which made `H264Decoder` read
Annex B when it has no avcC (H.264 in AVI).

## Why

Raw H.264 elementary streams (`.h264`, `.264`, `.h26l`, `.avc`: an encoder's or a camera's output, `ffmpeg -c copy
-f h264`) are Annex B with nothing around them. The decoder reads Annex B now; what is missing is a demuxer that cuts
the stream into pictures and says what the stream is.

## What FFmpeg does (6.1, checked on libx264 streams)

- Packets: its H.264 parser cuts the stream into access units, a picture a packet (a field a packet in field
  pictures), IDR pictures flagged as keyframes. No timestamps at all (pts and dts N/A); durations from the SPS's VUI
  timing in a time base of 1/1200000 (40000 at 30 fps), the stream's average rate 25 (`-framerate`'s default).
- Frames: `ffmpeg -i x.h264 -f framemd5` gives them at 0, 1, 2, ... in a time base of the VUI's frame rate (1/30,
  1/24), 1/25 without VUI timing.
- No duration, no seeking (a raw stream has no index).

## Proposal

1. **`H264Demuxer`** (Containers), detected by `Demuxer.Open` from a start code and an SPS among the first units, as
   `AdtsDemuxer` and `Mp3Demuxer` are by their headers. A new public type: an API decision, in the next minor version.
2. **Packets:** access units as FFmpeg's parser cuts them (7.4.1.2.3: a new one at an access unit delimiter, SPS, PPS
   or SEI after a picture's slices, or at a slice whose first_mb_in_slice is 0), Annex B as they are (the decoder reads
   them), keyframes at IDR pictures. Checked against ffprobe's packets (size, MD5, keyframe flag).
3. **Times:** a time base of 1 / the frame rate (the VUI's, else 25 as FFmpeg's), packets at 0, 1, 2, ... in decoding
   order, a tick each.
4. **Stream facts** (width, height, frame rate) need the SPS, which only the H.264 package reads: see the decisions.
5. **Seek:** not supported (`NotSupportedException`, as raw AAC and MP3); a thumbnail decodes from the start.
6. **Samples:** libx264 streams with and without B pictures, with and without VUI timing, written with
   `-f h264`; their frames against FFmpeg's framemd5 (relative times), their packets against ffprobe's.

## Decided

Asked with the multiple-choice prompt; the owner took each proposal (2026-11-09).

1. **The stream's facts. Decided:** a shared SPS reader. The SPS fields a demuxer needs (the size and cropping, the
   VUI's timing) move into a small file in src/Shared, linked into Containers as `Vlc.cs` is, with a test that it
   agrees with the decoder's `SequenceParameterSet` on every sample's SPS. `VideoStreamInfo` then has the size and
   rate, and `VideoProbe` needs no decoding.
2. **Frame times. Decided:** from 0, as FFmpeg's command line numbers a raw stream's frames. The demuxer marks its
   packets so the decoder doesn't shift them; AVI keeps its shift (#453, #455).
