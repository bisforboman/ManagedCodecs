# The road to 0.1.0 (2026-10-27)

**Done, 2026-10-27.** All six pull requests merged: XML docs (#152), the package readme (#153), exact pins (#154),
the login check (#155, run once in `release`: accepted), the release (#156: 0.1.0 on nuget.org, tagged, a fresh
project installed it, decoded bit-exact and published with Native AOT without warnings) and package validation
(#157). One rule changed afterwards: the validation baseline follows every release, not only a new minor version
(CLAUDE.md, Releases).

0.1.0-preview.3 is on nuget.org, and the public API was reviewed before it (2026-10-26-api-before-0.1.0.md). What
still stands between the previews and a stable 0.1.0 is less the API than what 0.1.0 promises and whether the
packages are ready to keep that promise. This record lists both: the owner's decisions, then the work, one
pull request each, with the check that proves it done.

## What 0.1.0 promises

Asked with the multiple-choice prompt; the owner took each proposal.

- **Compatibility. Decided:** from 0.1.0, a change to the public API ships only in a new minor version (0.2.0, ...)
  with a "Breaking changes" entry in CHANGELOG; a patch version (0.1.1) only fixes, its API the same; 1.0 is a
  decision of its own, later. What enforces it: PublicApiAnalyzers already shows every source-level change in a pull
  request; package validation (`EnablePackageValidation` with `PackageValidationBaselineVersion` 0.1.0, turned on
  right after the release) compares each build's binaries with 0.1.0's. README's Getting started and CHANGELOG's
  header say "until the API is frozen"; they say what the policy is instead.
- **One version for all packages, pinned.** The codec packages use seven of ManagedCodecs.Core's internals
  (`AdtsHeader`, `AudioFrame.DropStart`, `PixelFormatExtensions.Of`, `VectorZip`, `VideoFramePool`, its `RentPlanes`
  and an internal `VideoFrame` constructor), so an H.264 package next to a newer Core can fail at run time. Today the
  packages depend on each other's version or newer and CHANGELOG asks users to keep them at one version.
  **Decided:** exact dependencies (`[0.1.0]`), which a `Directory.Build.targets` gives every project reference
  (prototyped: the packed nuspecs read `version="[0.1.0-test]"`, the meta-package's five dependencies included). The
  alternative, making those internals public, would put a pool, a SIMD helper and an ADTS parser into the frozen API.
- **Target framework. Decided:** net10.0 only (an LTS release); no net8.0 build.
- **When. Decided:** 0.1.0 as soon as the work below is merged; nothing on README's Open list changes the API.

## Work, one pull request each

1. **XML documentation in the packages.** The packages hold the assemblies without their documentation files, so an
   IDE shows no descriptions. `GenerateDocumentationFile` for the src/ projects (the condition PublicApiAnalyzers
   uses), and doc comments for the public members that have none: 36 in Core, 16 in Containers, 2 in AAC, 1 each in
   H.264 and MJPEG (CS1591, an error under `-warnaserror` once the file is generated). Done when a packed package's
   `lib/net10.0/` holds the `.xml`.
2. **A package readme.** nuget.org shows none (`PackageReadmeFile` is not set). A short `PACKAGE.md` (what the
   packages decode, the example from README, links to the repository's docs), shared by every package; README itself
   is too long, and its relative links break on nuget.org. Done when the next preview's page shows it.
3. **Exact dependencies** (the decision above): `Directory.Build.targets`, and CHANGELOG's header saying why.
4. **A dry run of the stable release's login.** `release.yml` publishes previews from the `prerelease` environment
   and stable versions from `release`, whose nuget.org trusted publishing policy has never been used: the first stable
   release would be its test. A `workflow_dispatch` job in the `release` environment that only runs NuGet/login, so
   that a mistyped policy shows before it matters.
5. **The release**, as before: CHANGELOG's Unreleased becomes `## 0.1.0 – date`, `tools/ship-public-api.py`.
   Afterwards, as for preview.1: a fresh project installs `ManagedCodecs` 0.1.0 from nuget.org, decodes a sample, and
   publishes with Native AOT without warnings.
6. **Package validation**, right after: `EnablePackageValidation` with `PackageValidationBaselineVersion` 0.1.0.

Pull requests 1 to 3 all change `Directory.Build.props` or its neighbour and CHANGELOG's Unreleased section, so they go
one after another, each branched from main after the one before has merged.
